7 testing principles (in plain English)

  • You can't test every possible input — it's impossible.
  • Testing shows bugs exist, it never proves they're all gone.
  • Bugs cluster — some modules break more than others.
  • Keep changing your testing approach ("pesticide paradox").
  • Finding bugs early saves time & money.
  • Not every test type applies to every project — it depends.
  • A failure isn't always the tester's fault.

Test Case & Design Techniques

how to write great tests

Sample test case — Login

IDTC1234
TitleVerify login with valid credentials
StepsLaunch URL → enter username → enter password → click Login
Test dataAdmin / admin123
ExpectedUser lands on dashboard
Why we write test casesThey're a checklist during execution, evidence of what was tested, and the base for smoke, regression & automation suites.

Equivalence Partitioning

Group inputs into classes, test one value per group.

ExampleField accepts 1–100 → test one alphabet, one special char, one empty, one valid number (50). No need to test all 100 values.

Boundary Value Analysis (BVA)

Bugs love edges — test just around the limit.

Example5MB upload limit → test 5119KB, 5120KB (=5MB), 5121KB.

Decision Table

Used when output depends on a combination of conditions.

ExampleSchool app: Holiday notification → sent to Parent ✅ Student ✅ Teacher ✅ Admin ✅ Principal ✅. Payment Due → only Parent & Admin.

State Transition

Used when behavior depends on the previous state.

ExampleATM: wrong PIN once → 2 chances left; wrong again → 1 chance; wrong 3rd time → card blocked.

Severity vs Priority

Severity S1 / Priority P1Login page completely broken → high impact, fix immediately.
Severity S4 / Priority P4Spelling mistake in footer → minor, fix whenever.

Handy terms

  • Defect Leakage — missed in QA, found in Production
  • Hotfix — urgent fix pushed straight to Production
  • Defect Triage — dev + tester meeting to find root cause
  • RCA — developer documents why the bug happened

API Testing Basics

backend testing

An API is like a waiter: it carries your order (request) to the kitchen (server) and brings back the food (response).

HTTP Methods — Employee Example

MethodPurposeExample
GETRead dataGet list of employees
POSTCreate dataAdd a new employee
PUTReplace entire recordUpdate all personal details
PATCHUpdate one fieldUpdate just the last name
DELETERemove dataDelete an employee

Status codes

RangeMeaningExamples
2xxSuccess200 OK · 201 Created
4xxClient error400 Bad Request · 401 Unauthorized · 403 Forbidden · 404 Not Found
5xxServer error500 Internal Server Error · 503 Service Unavailable
401 vs 403 — interview favorite401 = server doesn't know who you are. 403 = server knows you, but you're not allowed in.

Postman essentials

  • Workspace — one per project, shared with the team
  • Collection — group requests by module/feature
  • Environment variable — e.g. {{baseURL}} = www.qa.com in QA, www.uat.com in UAT
