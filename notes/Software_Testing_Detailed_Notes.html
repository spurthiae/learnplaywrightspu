Phase 1 details

Client SPOC gives requirements → FRS document. Tech decided: Frontend (Angular/React/Vue/Node), Backend (.NET/Java/Python), APIs (REST/RPC/SOAP/GraphQL), DB (SQL/MongoDB/DynamoDB). Architect finalizes HLD.

Phase 2 details

UI/UX designers produce HLD (architecture) and LLD (screen-level design, e.g., in Figma).

Real example — WhatsApp requirement list (46 features)Create account, sync contacts, send/receive messages, voice/video call, security & privacy, e2e encryption, 2-step verification, status upload, broadcast, groups, drafts, edit message, AI chatbot, channels, backup, notifications, archive, starred messages, block contact, live location, lock chat, and more.

ModelHow it worksBest for / Note

Artifact hierarchy

 │   ├─ User Story 1 (Product Backlog Item)
 │   │    - Description / Acceptance Criteria

 ├─ Feature 2 (User Story 7, 8)

Product Backlog = full master list of all user stories. Sprint Backlog = subset picked for the current sprint only.

Product Owner / BA

  • SPOC from client; writes Epics/Features/Stories
  • Sets & re-prioritizes work
  • Reviews test plan & test cases
  • Decides disputed defects
  • Signs off completed stories

Scrum Master

  • Manages & motivates team
  • Schedules all meetings
  • Facilitator — removes blockers
  • Arranges KT for new joiners
  • Provides infrastructure/access

Tester responsibilities in Agile

  1. Understand Epics/Features/User Stories (clarify with PO)
  2. Write Test Plan → reviewed by SM & PO
  3. Write Test Cases → reviewed by peer & PO
  4. Set up test environment & data
  5. Execute tests, report/track/retest defects, write automation
  6. Test Closure: Test Report, Defect Report, RTM

STLC — Software Testing Life Cycle

Principles & 6 phases
▶

7 testing principles

  • Exhaustive testing is impossible
  • Testing shows bugs exist — never proves zero bugs
  • Defects cluster — some modules break more ("defect clustering")
  • Repeating identical tests stops finding new bugs ("pesticide paradox") — vary your approach
  • Early defect detection saves time & money
  • Testing type depends on context — not everything is tested everywhere
  • A failure isn't only the tester's fault

  3. Invalid username + valid password → error

Why we document test cases

  • Checklist during execution
  • Usable by a different tester
  • Evidence of what was tested
  • Basis for Smoke & Regression suites
  • Basis for Automation
  • Basis for Test Reports

Alt paths: Reopen (still broken) · Rejected (not a bug) · Deferred (pushed to future sprint)

Severity vs Priority

S1 / P1Login completely broken → major impact, fix now
S4 / P4Footer spelling mistake → minor, fix whenever

They're independent: D2 = S4,P1 and D4 = S1,P4 both occur in practice.

Handling a disputed defect

  1. Show proof from Epic/Feature/Story/Design doc
  2. Set up a call with Developer + PO
  3. Explain the defect
  4. If PO agrees → developer fixes; else it stays Rejected

Special scenarios

  • Same bug reappears after closure → don't reopen the old one, file a brand-new defect
  • Defect leaked to Production → check config, data, volume, or environment mismatch; add a missing test case if one didn't exist
  • Intermittent issue → doesn't appear consistently

Key terms

  • Hotfix — urgent fix released directly to Production
  • Defect Leakage — missed in QA, found in Prod
  • Defect Triage — dev+tester call to find root cause, tester reproduces live
  • RCA — developer documents why the bug happened
  • Defect Density = Defects ÷ Software Size
Automation scale1 story ≈ 45 test cases · Smoke ≈ 45 · Regression ≈ 400–2400+ test cases, often automated (e.g. with Playwright).

Status codes

RangeMeaningExamples

5xxServer error500 Internal Server Error · 502 Bad Gateway · 503 Service Unavailable
401 vs 403401 = server doesn't know who you are. 403 = server knows you but you lack permission.

Postman essentials

  • Workspace — one per project, shared with team
  • Collections — group requests by module; import/export/run whole collection
  • Global vs Collection variables — collection-level value overrides global (e.g. global x=30, collection x=45 → resolves to 45)
  • Environment variables — {{baseURL}} = www.qa.com in QA, www.uat.com in UAT
